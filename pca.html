PCA factory backend

The server side of an operations app for a factory that makes custom stands, signs and boxes: projects, task approvals, purchasing records, deliveries and team chat.

The problem.

Work moved through paper, phone calls and group chats. Supervisors could not see which step a project was on, what had been spent, or where finished work had gone. Most staff are not technical, so the system has to be simple to use and hard to misuse.

What I built.

I am the backend and DevOps engineer. A teammate builds the web frontend against an API contract I publish.

  • Access control on every request. Each endpoint checks both the action and the user's membership of that project, on the server, deny by default.
  • Money and quantities kept exact. Decimal types in PostgreSQL, never floating point. Expenses are corrected or voided with a reason and a history row, never edited in place.
  • Every important change is atomic. The state change, its audit record and its event are written in one database transaction; a background worker picks the events up from an outbox table.
  • Private file storage. Uploads go through the API, are checked by type signature and size, and are only served once verified.
  • One API contract. Endpoints are defined once; the OpenAPI document and a typed client for the frontend are generated from that definition and checked in CI.

How it ships.

  • Two small container images (API/worker and a one-time release job), non-root, with no package manager inside.
  • Docker Compose stack behind Caddy on separate internal networks; databases are never exposed.
  • A deploy script that pulls images by digest, runs migrations once, checks health, and puts the previous release back if anything fails.
  • CI on GitHub Actions: lint, types, unit and integration tests, a database upgrade check, secret scanning (gitleaks), workflow checks (zizmor) and image scanning (Trivy).

Where it stands.

The application features are built and tested. The container and deployment pipeline is being finished now. It has not gone into production yet.

The code belongs to the client and is not public. I am happy to walk through the design in an interview.
